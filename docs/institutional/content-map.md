# Aurora Meridian - Content Map

### Status

Approved for content architecture.

### Purpose

Este documento define o mapa de conteúdo institucional da Aurora Meridian.

Seu objetivo é transformar a estratégia institucional em uma arquitetura narrativa verificável antes da implementação definitiva de copy, UI e páginas.

O Content Map define, para cada unidade narrativa:

- Purpose;
- User Question;
- Message;
- Evidence;
- CTA;
- Next Step.

A regra central é:

> Nenhuma seção deve existir apenas porque ficaria bonita.

Cada seção precisa exercer uma função clara dentro da compreensão progressiva da instituição.

# 21 - Proof Architecture

Claims institucionais devem, quando possível, seguir:

```text
ATTRIBUTE 
    ↓ 
CAPABILITY 
    ↓ 
PROCESS 
    ↓ 
VALUE
```

Exemplo:

```text
Technology 
    ↓ 
Data & Analytics 
    ↓ 
Research Infrastructure 
    ↓ 
Expanded Analytical Capability
```

Outro exemplo:

```text
68 Professionals 
    ↓ 
Investment + Research + Risk + Operations 
    ↓ 
Specialized Organization 
    ↓ 
Institutional Capability
```

Claims aprovados no Master Project Brief podem ser utilizados quando pertinentes.

Entre eles:

- R$ 12,4 bi AUM;
- 68 profissionais;
- 320+ relações institucionais;
- 85 mil+ investidores alcançados;
- evolução histórica de AUM;
- performance aprovada;
- rankings;
- prêmios;
- parceiros;
- histórico institucional;
- equipe.

A presença de um número não constitui, por si só, uma seção.

A pergunta deve ser:

> O que essa evidência ajuda o visitante a compreender?

# 23 - Narrative Rules

### Rule 01 - Institution Before Product

Apresentar a instituição antes das estratégias.

### Rule 02 - Thesis Before Capability

Explicar a lógica antes da capacidade.

### Rule 03 - Capability Before Strategy

Apresentar capacidades antes do produto.

### Rule 04 - Process Before Promise

Mostrar processo antes de qualquer promessa.

### Rule 05 - Risk Before Product Conviction

Mostrar disciplina de risco antes de aprofundar estratégias.

### Rule 06 - Evidence Before Authority

Claims institucionais devem estar ligados a evidências aprovadas.

### Rule 07 - Demonstration Before Declaration

Demonstrar competência em vez de apenas afirmar competência.

### Rule 08 - Access After Understanding

Solicitação de acesso deve surgir depois da compreensão.

### Rule 09 - Progressive Disclosure

Cada página deve aprofundar uma perguntar sem duplicar integralmente outra.

### Rule 10 - No Artificial Complexity

Não criar conteúdo apenas para aumentar a sensação de sofisticação.

# 24 - Language

O site público deve ser integralmente em português do Brasil.

Termos institucionais em inglês podem permanecer quando fizerem parte da nomenclatura da marca, estratégia ou conceito estabelecido.

Exemplo:

- Independent Investment Management;
- Macro Intelligence;
- Relative Value;
- Global Opportunities;
- Research;
- Risk Management;
- Request Access, caso definido como nomenclatura de interface.

A regra geral é:

> O visitante brasileiro deve compreender a mensagem sem depender de domínio do inglês.

# 25 - Legacy Content Migration

O estado atual do código contém conteúdo de uma fase anterior do projeto, incluindo:

- "Beyond the market radar";
- conteúdo de "case fictício";
- dados ilustrativos;
- estratégia/produto anterior;
- CTA "Explore the opportunity";
- `/opportunity/access`.

Esse conteúdo não deve ser considerado a fonte de verdade narrativa para a nova experiência institucional.

A migração deve ocorrer em Sprints posteriores.

Nesta Sprint:

```text
Legacy Content 
    ↓ 
Identificado 
    ↓ 
Mapeado 
    ↓ 
Não reutilizado como fonte estratégica
```

Nenhum componente legado deve ser reescrito somente para concluir esta Sprint.

# 26 - Content Decision Test

Antes de adicionar qualquer nova seção, responder:

### 1. Purpose

Por que esta seção existe?

### 2. User Question

Qual pergunta do visitante ela responde?

### 3. Message

Qual é a única mensagem principal?

### 4. Evidence

Como demonstramos essa mensagem?

### CTA

Existe uma ação relevante?

### 6. Next Step

Para onde o visitante deve ir depois?

Se não houver respostas claras, a seção deve ser reconsiderada.

---

# 27 - Definition of Done

A Content Architecture está concluída quando:

- a narrativa institucional está definida;
- a homepage possui Content Map;
- cada seção possui Purpose;
- cada seção possui User Question;
- cada seção possui Message;
- cada seção possui Evidence;
- cada seção possui CTA quando necessário;
- cada seção possui Next Step;
- as páginas institucionais possuem responsabilidades claras;
- as estratégias possuem função narrativa definida;
- Research possui função definida;
- People & Culture possui função narrativa definida;
- Institutional Access possui função definida;
- a arquitetura respeita progressive disclosure;
- claims aprovados podem ser utilizados sem placeholders artificiais;
- o conteúdo público está orientado ao contexto brasileiro;
- o conteúdo legado está identificado;
- nenhuma nova dependência técnica foi criada;
- nenhuma alteração de UI é necessária para concluir a Sprint.
